# Decisions and Open Questions

This is the running log for the project. Add decisions with their date and reason. Never rewrite past entries; add a new entry that supersedes them.

## Origin (2026-10-22)

The idea is a site that shows how to build agent solutions properly, for developers and enterprises. It should have clear diagrams, strong visuals, and demos and samples people can try on the spot, with ThunderID applied as the implementation. It came from comparing the new thunderid.dev landing page with small solution-focused sites that explain one problem very clearly.

## Recommendations not yet decided

- **Demo, phase 1:** replay traces recorded from a real Wayfinder run against a tagged ThunderID release, plus a one-command local run. Build a hosted sandbox only if people drop off at the local run. GitHub Pages cannot host one anyway.
- **Voice:** standards-first (OAuth, RFC 8693, CIBA, RFC 8707, ID-JAG), with ThunderID as the implementation, for credibility with enterprises.
- **Status chips:** label each pattern Supported, Partial or Planned in ThunderID. Honest gaps are a differentiator.
- **Scope:** identity and authorization of agents only. Not orchestration, memory or evals.

## Open questions

Pattern order, tech stack, custom domain, Wayfinder fixes, pattern 7 and ownership were settled on 2026-10-22; see Decisions.

- **Scaffold PR:** the `site-scaffold` branch goes to `main` through a pull request on `sahandilshan/agent-identity-patterns`, merged once CI passes.
- **Target ThunderID release:** the latest stable release is v1.0.1 (2026-08-25), but every status claim so far was code-inspected on main, and recent agent work is not in v1.0.1. Target v1.0.1 or the next release? This sets the launch date; until it is chosen every status entry stays Unverified.
- **Dark theme:** needed at launch? The approved mock is light only.
- **Status labels in the mock:** proposals, verified against the target release before launch. "Govern who may call the agent" shown as Supported (the plan said "configured pattern"); ID-JAG shown as Partial (the plan said "supported with caveats"); LLM providers without static keys shown as "To verify", because "documented pattern" is not one of the three labels.
- **Site name:** "Agent Identity Patterns" is a working title.
- **Author line:** the footer needs an author and affiliation line; Sahan leads Agent Identity and AI capabilities for ThunderID, and disclosing that builds trust.
- **Run it yourself:** should the one-command local run use the same patched Wayfinder copy until the upstream fixes ship? Recommendation: yes, so what people run matches what the site replays.
- **Patch set location:** where the pinned, patched Wayfinder copy lives. Recommendation: patch files in this repository against a pinned ThunderID tag, so every fix is visible and drops away when upstream ships it.
- **Upstream issue:** the Wayfinder issue (chat gate token validation, backend audience default, ID token audience, README key name, README CIBA order, scheduler retries, unauthenticated demo trigger) is drafted and not yet posted.
- **Logo:** ask the ThunderID maintainers how the name and logo may be used, and read the LF trademark policy.
- **Multi-agent scene:** its shape once thunder-id/thunderid#5662 lands. Candidate: the Concierge hands a narrowed task to a worker agent.
